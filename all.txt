3. FACULTY TEACHER WORKSPACE, ACCOUNT SETTINGS & PRIVACY SAFEGUARDS
================================================================================
The Teacher Workspace is purpose-built for classroom instruction and continuous
assessment. It isolates faculty from administrative data and preserves student
confidentiality:

• Landing Page Confinement:
  When logged in as a teacher, the Director Portal and Records Office cards
  are completely hidden from view. Only the Teacher Workspace card is rendered.
• Sidebar Sanitization:
  - Quick Search (5-digit student dossier lookup) is hidden from the teacher
    sidebar to prevent unauthorized browsing of unassigned student files.
  - Sidebar contains the 7 essential teaching views:
    1. Dashboard: Welcome overview, active section counts, quick links.
    2. My Classes: Roster of students strictly in assigned sections.
    3. Mark Entry: Spreadsheet-like assessment scoring for assigned subjects.
    4. Adjustments: Audited mark modifications with mandatory reason logging.
    5. Rankings: Section rankings scoped to the teacher's assigned classes.
    6. SMS to Parents: Targeted messaging to parents of assigned students.
    7. Account Settings: Self-service credential & profile updates.
• Teacher Account Settings & Self-Service:
  - Teachers can edit their own login credentials: username, password, email,
    and phone directly via the Account Settings interface.
  - Changing password requires cryptographic verification of the current password
    via bcrypt.compareSync.
  - Updating username immediately re-issues a signed JWT token and updates
    the active session smoothly without forcing unexpected re-logins.
• Backend Hard Barriers:
  - GET /api/audit/logs: Blocked with HTTP 403 Forbidden.
  - GET /api/audit/stats: Blocked with HTTP 403 Forbidden.
  - GET /api/parents: Blocked with HTTP 403 Forbidden.
  - GET /api/teachers: Blocked with HTTP 403 Forbidden.
  - GET /api/users: Blocked with HTTP 403 Forbidden.
  - GET /api/students: Automatically scoped to assigned classes and sections.
  - GET /api/students/:id: If student is outside assigned classes, blocked with
    HTTP 403 Forbidden. For assigned students, audit_history is returned as an
    empty array [] to conceal institutional audit logs.
  - GET /api/search/global: Returns only students enrolled in assigned classes;
    returns empty lists for teachers and parents.

4. ACADEMIC STRUCTURE, DYNAMIC SECTION MANAGEMENT & CURRICULUM SUBJECT MATRIX
================================================================================
Lake Side Academy operates an 11-level academic tier spanning Kindergarten
through Grade 8 with flexible, dynamic section management:

• Class Levels (11 Classes):
  - Kindergarten: KG 1, KG 2, KG 3
  - Primary Cycle 1: Grade 1, Grade 2, Grade 3, Grade 4
  - Primary Cycle 2: Grade 5, Grade 6, Grade 7, Grade 8

• Baseline Standardized Sections (32 Total Active Default Sections):
  - Purged Sections D and E across all grades and kindergarten levels.
  - Standard Baseline: Classes default to 3 sections: Section A, Section B, Section C.
  - Grade 5 Exception: Section C is removed from Grade 5; Grade 5 strictly has
    only Section A and Section B (2 sections).
  - Breakdown:
    * KG 1 - KG 3: Sections A, B, C (3 sections each = 9)
    * Grade 1 - Grade 4: Sections A, B, C (3 sections each = 12)
    * Grade 5: Sections A, B (2 sections = 2)
    * Grade 6 - Grade 8: Sections A, B, C (3 sections each = 9)
    * Total Baseline: 32 sections.

• Dynamic Section Addition & Deletion Controls:
  - Executive Administrator and Directory staff can dynamically add sections
    to any class (e.g., adding Section D to Grade 8, so only Grade 8 has D,
    while other classes remain A - C).
  - Sections can be deleted dynamically via DELETE /api/academic/sections/:id.
  - Deletion Safeguard: A section can only be deleted if it has 0 enrolled students.
    Attempting to delete a section with active student assignments is rejected
    with HTTP 400 Bad Request to maintain relational integrity.

• Official Curriculum Subjects & Official Codes:
  Curriculum subjects are permanently badged and sorted by official code:
  - [MATH] Mathematics
  - [ENG]  English Language
  - [AMH]  Amharic Language
  - [SCI]  General Science
  - [SOC]  Social Studies
  - [ENV]  Environmental Science
  - [ICT]  Information & Communication Technology
  - [CIT]  Citizenship Education
  - [HPE]  Health & Physical Education
  - [PVA]  Performing & Visual Arts

• Subject Distribution per Academic Cycle:
  - Kindergarten (KG 1 - KG 3):
    [MATH], [ENG], [AMH], [HPE], [PVA]
  - Primary Cycle 1 (Grades 1 - 4):
    [MATH], [ENG], [AMH], [ENV], [HPE], [PVA]
  - Primary Cycle 2 (Grades 5 - 8):
    [MATH], [ENG], [AMH], [SCI], [SOC], [CIT], [ICT], [HPE], [PVA]

• Class & Grade Filter Scopes:
  - "All Classes & Grades (KG 1 - Grade 8)"
  - "All Kindergarten (KG 1 - KG 3)" (parameter: class_id=ALL_KG)
  - "All Primary Grades (Grade 1 - Grade 8)" (parameter: class_id=ALL_PRIMARY)
  - Individual Class & Section selection

6. CONTINUOUS ASSESSMENT & RANKING ENGINE
================================================================================
• Assessment Benchmarks (Term Dropdown Removed):
  The system uses direct Assessment Benchmarks rather than redundant term selects:
  - "ALL" (Full cumulative year / semester average)
  - "Mid" (Midterm Assessment)
  - "Final" (Final Examination)
  - "Tests" (Continuous Classroom Tests)
  - Shorthand Prefixes:
    "F." represents First Semester (e.g., F.Mid, F.Final, F.Tests)
    "S." represents Second Semester (e.g., S.Mid, S.Final, S.Tests)
  The backend automatically resolves benchmark prefixes to the correct semester.

• Ranking Engine Rules:
  - Algorithm: Standard Competition Ranking (1224 tie formula).
  - Medals:
    Rank 1: 🥇 Gold Medal & Bold typography
    Rank 2: 🥈 Silver Medal & Bold typography
    Rank 3: 🥉 Bronze Medal & Bold typography
  - Top 10 Leaderboard: Special highlighted styling with a minimum 50 score
    qualifying threshold (students with 0 or unentered marks are excluded).
  - Empty State: If no students are ranked, renders "No rankings available".
  - Scope Options:
    * Primary Cycle 1 (Grades 1 - 4)
    * Primary Cycle 2 (Grades 5 - 8)
    * Grade 1 - 8 (All Primary School)
    * Single Section / Class

7. CLASS & PARENT SMS BROADCAST (WHOLE SECTION & INDIVIDUAL STUDENT TARGETING)
================================================================================
• SMS Gateway Integration:
  Integrated directly with SMSEthiopia API v2.
  - Sender ID: LAKESIDE
  - Supports live dispatch to real Ethiopian mobile numbers (+251 9X XXX XXXX).
• Selected UI Buttons High-Contrast Overhaul:
  In TeacherSMSPage and Admin SMS Broadcast, selected class buttons render with
  vibrant high-contrast states in both dark and light modes:
  - Dark Mode: Glowing purple accent tint (rgba(124, 58, 237, 0.28)) with
    crisp #A78BFA solid border, active bullet indicator, and bold white text.
  - Light Mode: Clean lavender surface (#EDE9FE) with vibrant violet border
    (#7C3AED) and deep purple text (#4C1D95).
  - Eliminates washed-out white-on-white text issues permanently.
• Two Recipient Targeting Modes for Teachers:
  1. Whole Section:
     Dispatches SMS notice to all enrolled students' parents across selected sections.
  2. Select Specific Students:
     Allows faculty to select exact individual students or subgroups within their
     assigned classes:
     - Real-Time Search: Instant character-by-character search by student name letters
       or 5-digit Student ID.
     - Select All / Clear All: One-click batch selection and de-selection.
     - Student Cards: Interactive cards showing student name, 5-digit ID, class
       section badge, and parent phone number.
     - Live Recipient Metrics: Instant calculation of matching students, selected
       students, and deduplicated parent recipients.
• Backend Multi-Student Targeting Support:
  Both POST /api/sms/broadcast and POST /api/sms/calculate-recipients natively
  support target_type: 'STUDENT' with student_ids: [10001, 10002, ...].
• Phone Deduplication:
  When broadcasting to a class or school where a parent has multiple enrolled
  children, the system deduplicates phone numbers to prevent redundant messages.
• Tokenized Result SMS Generator:
  Auto-generates student assessment reports directly from the SQLite database:
  "Lake Side Academy Result: Hana Alemu (10001) | Math: 88, Eng: 92 | Total: 180 | Rank: 2nd"
  Can be dispatched directly with an Assessment Benchmark without requiring term_id.
• Real-time Parent SMS Simulator:
  Interactive simulated mobile phone interface for instant verification of
  dispatched SMS broadcasts, delivery receipts, and parent message logs.

8. STUDENT REGISTRATION, 5-DIGIT IDS & DOSSIER SYSTEM
================================================================================
• Immutable 5-Digit Student ID:
  Unique 5-digit number (10001+) assigned sequentially at registration and
  immutable across the student's entire tenure at Lake Side Academy.
• Multi-Child Parent Linking:
  Same parent phone number can be linked to multiple children (e.g., siblings),
  while preventing accidental duplicate student registration with the same name
  and parent contact.
• 7-Tab Student Dossier:
  1. Overview: Bio, 5-digit ID, class, section, roll number, status.
  2. Parents & Guardians: Primary and secondary contacts, phone, occupation.
  3. Academic Results: Current year breakdown by subject, assessment, and scores.
  4. Academic Summary: Cumulative total points, maximum points, and percentage.
  5. Multi-Year Academic History: Historical grades and section records.
  6. SMS Communication Log: Chronological history of all messages sent to parents.
  7. Security Audit Trail: Complete data modification diffs (Admin only).
• Grade Promotion Wizard:
  Promotes students to the subsequent grade level (e.g., Grade 7B -> Grade 8A)
  while permanently preserving previous academic year records in student_history.

11. SECURITY, AUDIT DIFF ENGINE & DATA INTEGRITY PROTECTIONS
================================================================================
• SQL Injection Prevention:
  100% of database interactions execute through parameterised prepared statements
  via node:sqlite DatabaseSync.
• Password Encryption:
  Passwords securely hashed using bcryptjs with 10 salt rounds.
• Security Audit Diff Engine:
  All state mutations (student registration, mark adjustments, settings updates,
  role changes) trigger automatic audit records logging old values, new values,
  user ID, IP address, and timestamp.
• Mark Modification Integrity:
  Direct overwriting of student scores is blocked. Modifications require an
  explicit justification string recorded in mark_history.
• Secret Admin Entrance:
  The admin portal is decoupled from public view and accessible exclusively via
  direct URL (/admin or /admin/login).
• Demo Backdoor Elimination:
  Demo credentials boxes and the /api/auth/demo-switch endpoint are disabled.

12. DATABASE SCHEMA ARCHITECTURE (node:sqlite WAL MODE)
================================================================================
The relational engine is powered by Node's built-in SQLite engine with WAL mode:
- PRAGMA journal_mode = WAL; (High concurrency, zero lockups)
- PRAGMA foreign_keys = ON; (Strict relational cascading & constraints)

Core Tables:
  1. school_settings             - Key-value institutional configuration
  2. permissions                 - Granular permission definitions catalog
  3. users                       - System user accounts (Admin, Directory, Teacher)
  4. user_permissions            - User-to-permission grant bindings
  5. academic_years              - Multi-year Ethiopian Calendar tracking
  6. terms                       - First, Second, and Average Semesters
  7. classes                     - KG 1 to Grade 8 definitions
  8. sections                    - Standardized sections (A, B, C, D, E per class)
  9. subjects                    - Curriculum subjects library with official codes
  10. class_subjects             - Class-to-subject curriculum assignments
  11. teachers                   - Teacher faculty profiles and staff IDs
  12. teacher_assignments        - Teacher-to-class/section/subject mappings
  13. students                   - Core student records with 5-digit unique IDs
  14. student_class_assignments  - Active and historical student enrollments
  15. parents                    - Parent and guardian contact directory
  16. student_parents            - Student-to-parent relational bindings
  17. assessments                - Tests, midterms, and final exam records
  18. marks                      - Student scores per assessment
  19. mark_history               - Audited score adjustments with justification
  20. student_history            - Historical academic and grade records
  21. sms_broadcasts             - SMS broadcast campaigns
  22. sms_recipients             - Individual SMS message delivery tracking
  23. announcements              - Notice board announcements
  24. audit_logs                 - Security and data mutation audit trail

17. DYNAMIC TEACHER-DEFINED ASSESSMENTS, MULTI-TEST INSTANCES & 100 MAX MARKS
================================================================================
• Unconstrained Multi-Instance Testing:
  Teachers are no longer restricted to a single fixed test per term.
  - Faculty can create and schedule tests multiple times throughout the term
    (e.g., Test 1, Test 2, Quiz 1, Pop Quiz, Midterm Exam, Final Exam, Bonus).
  - Assessment Types Supported:
    * 'Test'   : Standard classroom quizzes, chapter tests, unit exams.
    * 'Mid'    : Midterm examinations.
    * 'Final'  : Comprehensive end-of-term semester examinations.
    * 'Bonus'  : Extra credit and achievement incentives per subject.
    * 'Custom' : Specialized project work, laboratory evaluations, oral presentations.

• Strict 100 Maximum Total Marks Policy:
  - The sum of max marks across all assessments for any given subject, section,
    and term cannot exceed 100 points:
      SUM(max_marks) <= 100.0
  - Live Subject Points Summary API:
    GET /api/assessments/subject-summary?class_id=X&section_id=Y&subject_id=Z&term_id=W
    Returns:
    {
      total_max_marks: 80.0,
      remaining_points: 20.0,
      assessments: [
        { id: 1, name: 'Test 1', assessment_type: 'Test', max_marks: 20 },
        { id: 2, name: 'Midterm', assessment_type: 'Mid', max_marks: 30 },
        { id: 3, name: 'Bonus 1', assessment_type: 'Bonus', max_marks: 5 }
      ]
    }
  - Server-Side Enforcement:
    POST /api/assessments validates that (current_total + new_max_marks) <= 100.
    If the limit is exceeded, the server rejects creation with HTTP 400 Bad Request:
    "Cannot create assessment: Total max marks for this subject would exceed 100 points."

• Teacher Mark Entry UI & Real-Time Progress Bar:
  - MarkEntryPage displays a real-time points allocation progress bar:
    * Total Points Configured / 100
    * Points Available to Allocate (Remaining Quota)
    * Clickable assessment selector chips with badge indicators ('Bonus', 'Test', etc.)
    * "Add Dynamic Assessment" modal with remaining points validation and warning.
  - Authentic Amharic Save Action:
    Primary save button maintains authentic Ethiopian educational terminology:
    'አስተካክል' (Adjust / Record).

19. DIRECTORY PROMOTION EVALUATION ENGINE & AUTOMATED PASSING THRESHOLD
================================================================================
• Director / Registrar Promotion Threshold Configuration:
  - Minimum passing promotion average cutoff is configurable in real time.
  - Persisted in 'school_settings' under key 'promotion_min_average' (Default: 50.0%).
  - Quick-select preset buttons in UI: 50%, 55%, 60%, 65%, 70%.
  - "Save As Default" button persists the selected threshold as the permanent policy.

• Automated Cumulative Performance Engine:
  - Endpoint: GET /api/academic/promotion-evaluations
  - Aggregates all marks scored by each student across all subjects in the academic year:
    * Cumulative Total Marks Obtained
    * Cumulative Total Maximum Points
    * Cumulative Overall Percentage Average: (total_obtained / total_max) * 100
  - Automated Status Decisioning:
    * If overall_average >= min_passing_average: Status = 'Promoted' (Emerald Badge)
    * If overall_average < min_passing_average: Status = 'Retained' (Amber Badge)
    * If no marks recorded: Status = 'Pending Evaluation' (Neutral Slate Badge)

• Class-Level Executive Summary KPIs:
  - Total Enrolled Students
  - Promoted Count & Percentage Rate (e.g. 93.3% Promoted)
  - Retained Count & Percentage Rate
  - Class-Wide Cumulative Average Benchmark

• Student Complete Details Modal:
  - Complete subject-by-subject score breakdown table:
    * Subject Name & Code
    * Marks Obtained / Max Marks
    * Subject Percentage
    * Subject Pass / Fail Status (Individual subject 50% cutoff)
  - One-Click Next Grade Advancement Form:
    * Pre-selects recommended next grade level (e.g. Grade 7 -> Grade 8)
    * Select target section and target academic year
    * Executes official re-enrollment preserving historical dossier.
